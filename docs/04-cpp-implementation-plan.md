# 叙演工坊：C++实施计划与首轮任务

版本：0.2-draft · 日期：2026-09-18  
用途：把产品与架构设计拆成可以直接实施的工作；本文是开发计划，所有任务当前均为未开始。

## 1. 本轮架构结论

采用C++20实现世界资料、推演、检索、版本、模型编排和持久化；原生界面采用Qt 6、QML及Qt Quick Controls；构建采用CMake，数据使用SQLite。Windows优先，随后完成macOS、Linux与Android适配。

正式Web版采用独立浏览器界面和C++服务端。网页建议使用TypeScript；服务端复用原生客户端使用的领域与应用库。Wasm只用于检验部分界面复用，不承担首个完整Web版的交付承诺。

用户提出的C++方向已经纳入计划，Qt、QML和Web界面方案是本版工程选择。C++并不限制多模型功能：模型能力通过网络协议接入；无需为每家厂商等待C++专用SDK。厂商协议处理、超时、结构化输出和用量统计仍需在本项目适配器内完成。

## 2. 首次开发要交付什么

首个可运行工程样例限定为“灰港议和”的两个角色、一个秘密、一件唯一物品和三个回合。样例只使用固定模型响应，不要求API Key。

实际操作流程：启动Windows应用 → 打开示例世界 → 查看人物及证据 → 单步运行三回合 → 暂停 → 关闭程序 → 重启 → 继续查看一致的状态 → 从已有回合创建一条分支。

这个样例验证六件事：UI与核心分离、命令去重、人物知识范围、状态原子提交、任务恢复、分支隔离。基础功能通过后再完善编辑器、真实模型和全书提取。

该样例是M0工程验证成果。它没有覆盖完整世界模板编辑、全书提取、多厂商真实互动和全部视图，因此不能标为用户所需的Windows完整首版。完整首版仍按M1—M5及P0验收交付。

## 3. 模块所有权与可复用范围

| 模块 | 负责什么 | 可以依赖 | 不应承担 |
|---|---|---|---|
| domain | 世界事实、卡片/实例、时间、分支、规则、不变量 | 标准C++值类型与少量已审定基础库 | Qt界面、网络和SQL |
| application | 用例、权限、事务提交、任务状态、预算 | domain与抽象仓储/调度接口 | 页面布局和厂商字段细节 |
| engine | 提取流水线、上下文、回合调度、候选变化 | domain、独立端口契约、provider接口 | 任意数据库写入和系统命令 |
| providers | 请求构造、流式解析、结束原因、能力/usage | HTTP传输接口、协议DTO | 人物知识授权和世界真相修改 |
| storage_sqlite | Schema迁移、查询、事务、备份、索引 | SQLite与领域DTO | 模型调用、界面回调 |
| platform_qt | 网络、事件循环、文件、系统凭据适配 | Qt和相应平台API | 剧情逻辑 |
| viewmodels | 列表模型、可编辑草稿、命令提交与状态显示 | Qt模型层、应用Facade | 私自提交世界状态、直接操作数据库 |
| ui/qml | 页面、控件、导航、可视化交互 | 已注册ViewModel及组件 | 业务重试、长期任务和密钥持久化 |
| server | 认证、工作区访问、HTTP/SSE、上传下载 | 无界面核心与服务端适配器 | 复制一套剧情规则 |
| web | 浏览器页面与交互、事件重连 | 共享Schema/语义协议 | 厂商长期Key和后台推演权威状态 |

所谓共用核心，是同一份源代码构建成各端的库或服务；不是把某台Windows生成的动态库复制到所有平台。跨平台构建按目标系统与架构分别完成。

应用服务调用引擎，引擎通过独立端口返回提案并请求查询，不反向链接应用服务实现；端口头文件由公共契约目标提供。CMake依赖图保持无环，最终组装入口注入具体实现。

## 4. 数据与Qt界面的连接方式

原生UI通过应用Facade提交版本化命令，命令语义与技术文档第12节一致。Facade立即返回受理/校验结果或job_id，后续通过订阅投递进度、状态变更和错误。

列表采用QAbstractListModel/QAbstractTableModel及分页加载，避免把全书所有段落或全部关系转成一个QML数组。ViewModel在GUI线程更新，后台线程只产生结果对象；Qt模型通知必须在所属线程发送。

普通表单使用独立草稿，保存时携带expected_revision。按钮禁用只能改善体验，不能替代核心的重复命令校验。页面关闭只取消界面订阅；如需暂停推演，由用户动作发送明确命令。

存储和网络层不认识具体窗口。应用退出时先阻止新任务，保存检查点和在途请求状态，再释放后台对象；不能只依赖某个页面析构函数完成备份。

## 5. 原生页面实施顺序

| 顺序 | 页面 | 第一版实现重点 | 后续增强 |
|---|---|---|---|
| 1 | 工作区与示例入口 | 新建/打开、任务恢复、明确错误 | 最近项目、项目概览 |
| 2 | 人物/世界条目详情 | 结构化表单、来源、修订保存 | 批量编辑、丰富排版 |
| 3 | 推演室 | 对话、当前状态、单步、暂停、待提交标记 | 导演面板、多视角与快捷键 |
| 4 | 小说导入与校对 | 章节预览、候选条目、原文证据 | 批量消歧和增量导入 |
| 5 | 时间/事件/关系/地图 | 列表先完整，基础图视图可交互 | 布局优化、更多筛选和复杂地图 |
| 6 | 分支比较与导出 | 差异、采纳、Markdown/JSON | 草稿整理、可视化报告 |

完整Windows首版仍需第五项的基础图视图；“列表先完整”只是实施顺序，不是删除用户要求的地图和关系功能。

## 6. 编辑器与图形视图方案

### 6.1 中文长文本

资料正文按章节/片段加载，保留只读原文与独立编辑草稿。对话使用可回收的列表代理，禁止无限追加到一个巨型文本控件。基于块ID和Unicode码点范围跳转，高亮时转换为Qt文本索引。

先实现普通文本/Markdown编辑、搜索、证据跳转、撤销/重做、保存与冲突处理；复杂富文本、协同光标和DOCX排版不进入第一轮。必须实测中文输入法预编辑、候选窗口定位、emoji、组合字符、选择复制和缩放。

### 6.2 地图、时间线、事件线与关系图

共享“世界坐标—屏幕坐标”转换、缩放、平移、选择和属性面板；各视图分别保留自己的语义。

- 地图第一版为地点层级、背景图和点/线标记；地点真实行程与图片像素坐标分开存储。
- 时间线按可比较的世界时间展示，未知/相对时间使用单独区域，不强塞进某一天。
- 事件线显示前置/因果，不把章节顺序伪装成因果边。
- 关系图默认显示选定人物的一至两跳关系，并可切换列表，避免全图拥挤。

初始渲染可用Qt Quick基础项和受限数量的图元；大量节点/边时先做视口裁剪、聚合和分页，再根据性能数据选自定义场景图绘制。布局计算放在CPU工作池，结果返回GUI；不能在每次拖动时重新计算全世界关系。

## 7. 构建与依赖策略

### 7.1 工具链

| 目标 | 建议工具链 | 验证要求 |
|---|---|---|
| Windows x64优先 | Qt 6对应MSVC工具链、CMake、Ninja | Qt与应用ABI一致，开发与发布构建分开 |
| macOS | 选定Qt版本支持的Xcode/Clang | 在实际macOS环境构建并验证发行包 |
| Linux | 选定发行版、Qt与GCC/Clang组合 | 记录运行库/图形环境，限定支持范围 |
| Android | Qt对应的SDK/NDK/JDK与ABI | 先arm64设备/模拟环境，文件和生命周期实测 |
| Web服务端 | Linux上的C++无界面构建 | 不链接Qt GUI/Quick，配置外置、可恢复运行 |
| 可选Wasm | 与选定Qt匹配的Emscripten | 独立构建配置，不影响Windows发行目标 |

具体版本由M0记录到依赖矩阵，先检查本机已有环境，再选择可取得的受支持组合；不把文档当日的最新版本直接当成发布必须版本。

### 7.2 依赖选择

应用层统一使用一套JSON值和校验适配，SQLite采用固定版本及编译选项，包含所需FTS5支持。中文切词、归档处理、Schema校验和测试框架分别列出候选库的版本、平台支持、依赖体积及授权方式。

依赖管理机制在M0选定一个主方案；同一库不混用系统包、自动下载和手工复制的不同版本。Qt SDK由独立工具链配置引用，CMakePresets只保存可分享设置，本机路径放在不提交的用户配置。

Windows安装包必须带齐需要的Qt/QML插件、图形/TLS运行组件和资源；清除对开发机安装路径的隐性依赖。发行时检查Qt模块与打包方式，相关选择影响开源或闭源分发方案，不能仅凭“动态链接”就认为所有条件自动满足。[Qt模块授权](https://doc.qt.io/qt-6/licensing.html)

### 7.3 命令约定

M0应提供并验证下列操作。以下是计划中的preset名，当前目录尚无可执行CMake工程：

```text
cmake --preset windows-dev
cmake --build --preset windows-dev
ctest --preset windows-dev
cmake --preset windows-release
cmake --build --preset windows-release
```

额外目标包括：check-contracts、core-tests、integration-tests和ui-tests。实际命令写进开发说明，并在干净环境验证后才标为可用。

## 9. 模型接入顺序

先完成固定响应与本地模拟HTTP服务，验证事件协议和故障；再根据用户已有凭据选择第一家提供商，不预先要求购买指定厂商。第二家优先验证不同原生协议，以暴露消息/输出格式差异。

全部首版路径仍包括OpenAI、OpenAI-compatible、Claude与Gemini；实现顺序按真实可用凭据调整。没有某类凭据时可以完成代码与Mock契约，但验收记录必须保留“未真实验证”。

每个新增适配器至少有：正常文本、结构化结果、流式碎片、usage、限流、拒绝、截断、取消、连接断开和未知请求状态样例。模型输出的状态提案仍经同一核心校验。

第一轮不实现跨厂商自动兜底链条。先允许作者对失败的未提交步骤选择另一个已授权提供商；测试通过后再实现预先配置的自动降级策略。

## 10. 首版参数建议与可调整项

| 参数 | 初始开发配置 | 说明 |
|---|---|---|
| 活跃人物 | 常用2—4人 | 工程样例2人，不能推断大规模角色已可用 |
| 提交顺序 | 单会话顺序回合 | 不以网络完成顺序决定角色行动 |
| 网络全局并发 | 默认2个请求，可配置 | 提取与推演共享调度，并尊重厂商限流 |
| 候选修复 | 每步最多1次模型修复 | 计入预算，失败进入人工处理 |
| 暂停 | 停止新调度，在途结果暂存 | 不保证厂商费用撤销 |
| 自动连续推演 | 默认20回合上限 | 用户可调整，始终受预算和停止条件约束 |
| 原文/图列表 | 分页或按场景加载 | 不设无证据的最大可用规模声明 |
| 凭据缺失 | 本地编辑和Mock可用 | 正式模型任务有明确提示 |

超时与缓冲上限由端点配置决定，在M0探针中确定合理默认；输出token、费用和次数各自设限。不能用一套过短总超时掩盖复杂模型的正常长响应，也不能没有任何上限。

## 11. 首轮不进入的工作

账号与云同步、模板公开市场、语音/视频、图片生成、复杂富文本、自由脚本插件、全图物理布局、数值战争系统和多人物同时行动裁决均不进入W0。它们按原产品优先级处理。

首个工程样例之后，基础地图、时间/事件线、关系图、模板导入和多模型真实推演必须继续完成，不能因为Mock演示可以运行就提前结束Windows首版。

## 12. 审查与交接记录格式

每个任务保留：状态、输入版本、产物文件、实际执行命令、测试环境、测试结果、已知限制、依赖阻塞和下一项任务。状态统一为未开始/进行中/待条件/完成；“待条件”必须说明缺什么，不能等同完成。

代码审查重点：所有权是否明确、异步回调是否越界、取消是否会重试、提交是否原子、私密内容是否提前进入检索、版本引用是否固定、C++业务代码是否被重复写入QML/Web。对行为重要的测试与修复一起提交。

后续开发先检查目录现状和这些任务记录；本次修改只更新计划书，没有安装Qt、编译应用、调用付费模型或生成安装包。
