适用基线：当前 Git 主分支及本地工作树；每次领取任务前以实际状态重新核对。本文是续建计划，不是从零搭建指南，也不是已完成声明。

## 1. 目标、事实与文档分工

当前优先交付：**空白首启 → 创建世界并导入本地小说 → 章节校正与切片 → 可追溯提取 → 人工校对 → 发布世界版本**。千万字小说处理是核心验收范围，不是可选演示。之后继续完成人物入场、通用多模型推演、分支比较与导出，最终完成 Windows 首版。

## 3. 不可回退的产品与安全边界

1. 正式程序、资源、默认数据库、发行包不得附带世界、人物、小说正文或固定剧情。测试数据只能处于测试目标或运行时临时目录，不能因为缺数据而自动生成演示世界。
2. 旧固定测试数据库兼容已获准彻底移除。对不再支持的格式显式拒绝，不能猜测转换、静默清库或覆盖用户数据库；保留原文件供用户自行处理。
3. 本地小说仅作为外部测试素材。默认不联网，不随仓库/安装包/诊断包发布；所有导入正文、模型输出和文档附件都是数据，不是可执行指令。
4. 当前已批准“模型抽样 1 步”的显式发送方式。批量发送需新增范围、提供商、预算、预计成本和确认步骤；不能把单步授权扩展为自动全书发送。
5. 原文不可变。压缩是带映射的派生视图，不能替换原文，也不能把删除描写的长度比例当作事实召回率。
6. 左项目、右工作区；全中文可见文案；保留语言接口、主题令牌与深浅主题。新页面/明显布局变化先说明范围并提供预览确认，已确认范围内的小修复不重复请求相同决定。
7. API 凭据只经安全存储/受控输入；不写进源码、命令参数、日志、截图、测试断言或提交。规划、普通回归与 CI 均不调用付费模型。
8. 不回填或伪造开发、测试、Git 时间。阶段完成后按真实时间提交与推送，不能用提交数量代替验收。

## 5. 实际模块边界与改动入口

| 当前目录 | 实际职责 | 开发约束 |
|---|---|---|
| `libs/domain` | 世界/来源/候选/人物/会话等值类型与规则 | 不引入 Qt、网络或 SQL；通用化状态不能依赖固定角色 ID |
| `libs/application` | 导入、提取、校对、版本、人物、会话等服务 | 长任务与提交规则放这里；逐用例收敛，不先做全库 Facade 重写 |
| `libs/storage_sqlite` | 查询、迁移、事务、快照、恢复 | 世界过滤/分页在查询层；跨对象提交保持原子性 |
| `libs/providers` | 厂商请求/响应转换、流式协议解析 | 不决定角色权限或写入世界事实 |
| `libs/providers_qt` | Qt 网络传输 | 线程归属、超时、取消、在途未知状态明确 |
| `libs/platform_native` | 原生凭据等适配 | Windows 已有实现；其他平台不足显式报告 |
| `libs/package` | JSON 与受限归档基础 | 导入校验、路径限制、原子性与源文隐私 |
| `ui/viewmodels` | 页面状态、草稿、异步结果桥接 | 现有部分直接访问仓储；按任务迁移，避免重复业务规则 |
| `ui/qml` | 控件、布局、主题、中文交互 | 不做数据库事务、批量模型调度或业务恢复 |
| `tests/engine`、`tests/synthetic_fixture.*` | 固定响应与合成状态测试 | 仅测试链接；不得重新放回生产 `libs/engine` |
| `tools` | 编译预览、契约校验、打包 | 保留一键入口；生产产物采用明确清单 |

当前 UI 广泛使用 `QVariantList`，并非已全面实现 `QAbstractListModel`；统一命令 Facade、有界后台协调器仍属待实施目标。最小 Qt Quick 组件测试已建立，后续需随功能增加覆盖。先对长列表和长任务补足边界，再按实测需要替换实现，不为了架构名称重写所有代码。

## 6. 适合 6sol high 的单任务开发流程

每次只推进一个主任务。不要给代理“完成全部剩余功能”或“重写整个前端”这样的无边界指令。

1. **恢复上下文**：读本文、状态文档、目标卡片；查看 `git status --short`、有关差异与最近测试。区分本轮修改和用户已有修改。
2. **定位最小读集**：公共头文件、对应实现、组装入口、相关测试、涉及的 QML。不得只凭搜索命中断言某功能不存在。
3. **明确契约**：写出输入/输出、不变量、失败分型、数据修订、跨线程归属、取消含义。协议或数据破坏性变更先明确兼容策略。
4. **先建回归**：修复任务尽可能先复现失败；新功能先补最小正常/非法/取消或重启测试。伪传输替代真实网络。
5. **实现一个纵向切片**：最小领域/仓储变更 → 应用用例 → ViewModel → 页面 → 验证；纯后端任务不强行修改 UI。
6. **分层验证**：运行卡片要求的检查，审查完整差异，确认未顺带改用户数据、默认权限、凭据或模型调用方式。
7. **交互确认**：涉及新页面或明显布局调整，提供真实程序深浅主题预览和可点击流程，记录用户确认；截图只证明外观，不代替交互测试。
8. **记录与交接**：填写命令、退出码、环境、结果、限制、变更文件和下一任务；更新看板状态及对应实现证据。
9. **阶段提交**：检查暂存清单和敏感/测试资产边界后，按用户已授权的阶段上传方式提交推送。网络/认证失败只报告，禁止覆盖远端或强推。

任务规模按可验证边界划分：

- S：一个明确行为或局部修复，依赖已满足，可单独回归。
- M：一条跨层用例；开始前拆成实现和验证小步骤，但保留一次完整验收。
- L：涉及多个独立用例、多个未知协议或大面积数据迁移；必须先拆卡，不直接开工。

遇到困难先缩小复现、查本地代码和官方文档；确有技能缺口时再审查并安装相关 skill。技能提供方法，不替代对本项目代码的核对。

### 并行与上下文管理

主代理负责接口、集成、文档与最终验收。子任务只适用于独立代码区域或只读审查；共享 `workspace_repository.cpp`、同一个 ViewModel 或同一个 QML 页时串行修改。子代理反馈必须包含路径、符号、依据和未验证项。

每次交接保留：目标、输入提交及未提交差异摘要、已做/未做、可复现命令、阻塞、下一步。结论依据已保存产物和测试，不依赖聊天里模糊的“刚才已完成”。

按需使用已有技能：C++ 用 `lazy-cpp-dev`；QML 用 `qt-qml`；布局用 `qt-ui-design`/`frontend-design`；CMake 用 `qt-cmake-project`；测试用对应 Qt 测试技能；提交前验证用 `verification-before-completion`。不要为每张卡同时加载全部技能。

## 7. 统一代码与资源规范

### 7.1 函数注释

所有新增/修改函数使用中文 Doxygen 风格 `/** @brief … */`。公开或有声明的成员函数在声明处记录契约；仅实现文件内的自由/辅助函数及测试函数在定义处记录；QML/JavaScript 函数采用同样的块注释格式。声明和定义不重复维护同一长说明。

参数、返回值、副作用、失败条件、线程归属或取消行为不直观时补充 `@param`、`@return` 或正文。命名 lambda 有独立业务含义时在绑定处解释。重要函数内部以简短 `//` 标出事务、边界校验、码点转换、异步生命周期和凭据使用点，不逐行复述语法。

旧函数注释逐模块补齐，XF-26 最后核查全库；在覆盖检查前不能声称“每个函数都已达标”。禁止注释包含私密素材或密钥。

### 7.2 状态与线程

- 原文、已发布版本与已提交状态不可静默改写；编辑使用草稿和预期修订。
- SQL 事务不跨网络等待；模型只能返回候选/意图，不能直接提交事实。
- GUI 线程只更新界面及所属模型；工作线程返回值对象，不跨线程操作活跃 SQL statement 或 QML 对象。
- 页面切换不能串世界、丢草稿或错误接收旧任务回调；异步结果携带工作区/世界/任务身份。
- 暂停停止新调度；取消不保证厂商退款。在途未知调用不自动重发，不返还未经核实的费用预算。
- 千万字文本按章/块读取，列表按需分页；批次与队列有界，禁止把整书长期塞入一个 QML 字符串。
- QObject 与智能指针所有权不得重复；退出、切换工作区、取消和迟到回调需要独立回归。

## 8. 验证门禁与真实命令

具体环境见[构建运行](06-build-and-run.md)。以下是**已有入口**：

| 修改类型 | 最小验证 |
|---|---|
| 纯文档 | 引用/链接、任务依赖和源代码核对；`git diff --check` |
| 领域/存储/应用 | `cmake --build --preset core-dev`、`ctest --preset core-dev`；先按构建说明配置 |

| 外部素材 | `XUYANFORGE_NOVEL_FIXTURE`；全书离线另设 `XUYANFORGE_NOVEL_FULL_OFFLINE=1` |
| 发行 | release 构建、打包脚本、产物清单和无 SDK 的干净 Windows 测试 |

界面与测试同时启用时，现有 CTest 名称为 `core_tests`、`stress_tests`、`tst_qmltests`、`tst_world_views_vm`、条件启用的 `contract_tests`，另有 `check-contracts` 构建目标；尚无完整 UI 端到端或通用 `integration-tests` 目标。无密钥持续集成已配置，实际远端结果见状态记录；检测器配置仍待实现。WSL 不复用 Windows 的 CMake 缓存目录。

## 9. 完成定义与阶段上传

单项任务只有满足以下条件才可“完成”：依赖满足；实现符合范围；失败路径有测试；要求的测试本次运行通过；中文注释和文档同步；没有夹带数据或密钥；UI 改动按要求确认；已知限制明确。

“代码存在”“通过编译”“伪传输通过”“真实模型质量通过”“用户确认”“发行验收通过”是不同证据，不相互替代。历史测试日志只能证明当时那次执行，不能证明之后的工作树。

每阶段至少形成一个可审查提交或一组内聚提交：实现与回归同批，文档更新进度，提交说明记录 XF 编号。提交标题、阶段说明和用户展示版本使用中文；机器版本号保留构建工具要求的格式。先检查已有未提交修改来源，不能把全工作树直接打包成一个无范围提交。推送普通分支更新，不重写历史。验收记录使用实际日期和测试基线；自动检查失败时先修复，不宣称阶段验收或软件发布通过。
