# 叙演工坊项目开发规范

生效日期：2026-09-29。覆盖 C++、QML、脚本、测试、文档、预览和发布。根目录 [AGENTS.md](../AGENTS.md) 引用本文，作为后续开发统一入口。

## 1. 执行流程与约束优先级

1. 阅读本规范、[执行计划](04-cpp-implementation-plan.md)、[状态记录](05-development-status.md)及[任务看板](07-development-task-board.md)。
2. 检查当前代码、分支、工作区差异和相关测试，保留用户已有修改；不按旧文档凭空假定代码状态。
3. 用户最新明确要求优先于旧计划、既有习惯和外部技能。技能用于改善方法，不能覆盖数据隔离、中文界面和注释要求。
4. 每阶段完成一个可验证用例：明确输入、输出、前置条件和失败行为，实施后验证、记录状态并上传。
5. 分别标记代码实现、本机测试、界面接通、远端验证和用户验收。没有证据的阶段不得标记完成。

## 2. 产品和架构方向

- 千万字小说的导入、章节识别、切片、主干提取、模型解析、证据回查和人工校对是核心，优先推进实质功能。
- 界面采用左侧项目列表、右侧工作区，减少重复导航和无意义步骤展示。可见界面变化先提出具体方案并提醒用户确认；已直接要求的中文化及样例清理已有授权。
- 提供浅色、深色主题，颜色、字体、间距通过统一主题接口管理；预留主题扩展和多语言接口。
- 保留[一键编译并预览](../一键编译并预览.cmd)。编译失败不能启动旧程序并报告成功；测试和截图必须使用隔离工作区。
- C++20 核心与 Qt Quick 界面分层，使用 CMake、SQLite。界面经视图模型调用应用服务，不直接操作数据库或拼接模型请求。

## 3. 禁止预置样例与污染

- 正式程序不得硬编码任何样例世界、人物、地点、小说段落、关系、任务、假进度或假模型结果。
- 全新安装、全新工作区和空白预览不含世界、来源、人物卡、候选和任务；空页面显示中文说明和可用入口。
- 禁止把样例放进初始化 SQL、资源、默认值、占位符、提示词示例、兼容映射、截图脚本和异常恢复路径。不得恢复已移除的旧测试兼容。
- 用户提供的小说只作外部本地测试素材，不复制到受跟踪文件、资源和发行包。私有原文、工作数据库、模型详细输出、密钥不入库。
- 自动化测试允许在测试目标内生成独占临时素材及内存替身；禁止正式目标链接或打包这些数据，禁止测试使用真实用户工作区。
- 检查范围包括源码、默认数据库、最近工作区记录、启动参数、已构建程序及部署目录。源码扫描不能证明旧程序和旧数据库没有污染。
- 清理前确认准确路径、来源及关联资产，仅处理已确认的开发样例；优先隔离备份。不能按名称猜测并删除用户创建或导入的资料。
- 不得添加按某个旧样例名称隐藏资料的产品补丁，应移除注入源并隔离旧产物。
- 发布必须从空暂存目录按白名单构建，不得直接压缩整个开发构建目录。

## 4. 全中文界面

- 所有产品提供的按钮、菜单、下拉选项、页签、提示、工具提示、状态、错误、弹窗标题和动作均使用简体中文。
- Qt 默认控件、文件选择框和确认/取消按钮同样验收；显式加载中文框架翻译并为关键动作提供中文标签，不能依赖系统语言。
- 中文验收逐页展开每个下拉、工具/右键菜单和文件筛选，实际打开确认弹窗并验证确认、取消路径；深浅主题均检查。首页截图、源文扫描或已加载词库均不能代替这些交互证据。
- Qt版本可能新增动作或缺少词条。框架补充翻译须按精确上下文和源文匹配，不宽泛替换用户内容；无翻译接口的内置提示应提供中文等效确认，不能直接移除安全确认。
- 内部枚举、数据库键和协议值保持稳定，显示层单独映射中文标签。内部 `candidate` 应显示“待校对”，不得直接作为选项展示。
- 未识别的内部状态显示“未知状态”等中文回退，不回退为英文代码。程序生成的默认工作区名称使用“默认工作区”，不用内部文件名充当可见选项。
- 用户输入的名称、小说原文、路径、网址、真实模型标识及文件扩展名保持原值，不能因中文化破坏数据和接口；它们不是产品自带的英文选项。
- QML 固定文案经 `qsTr()`，Qt C++ 固定文案经 `tr()` 或明确翻译上下文；使用占位符格式化参数，不拼接不完整词条。
- 当前仅开放简体中文。其他语言须完成词条、回退、动态重译和交互验收后开放，保留扩展接口不等于提供未完成的英文界面。

## 5. 详细中文注释

### 5.1 每个函数的契约

使用普通中文块注释，不使用 `@brief`、`@param`、`@return` 等 Doxygen 标签。禁止只有“查询数据”“设置参数”的一句话；简单函数可以简短，但下述语义必须明确：

- 功能：解决什么问题、操作哪个范围、调用前必须满足什么条件。
- 参数：按签名逐个解释用途、单位、输入/输出方向、合法范围、默认值和空值含义。指针、引用、回调说明所有权和有效期；无参数写“无”。
- 返回：解释返回值、成功/失败结构及空结果；无返回值写“无”。构造函数注明完成初始化，析构函数注明释放的资源。
- 失败：说明实际校验错误、修订冲突、异常或错误传播路径，不写代码无法保证的承诺。
- 副作用：说明数据库、文件、网络、缓存、设置和信号变化；只读函数说明其只读范围。
- 线程与生命周期：异步函数注明调用线程、执行线程、回调线程、捕获对象有效期、取消及退出语义。

统一模板：

```cpp
/*
 * 功能：查询指定世界中的待校对候选，总数与本页条目来自同一读快照。
 * 参数：
 *   world_id：输入，世界稳定标识；不能为空。
 *   limit：输入，本页最多返回的条目数，范围由接口校验明确限定。
 *   offset：输入，从零开始的条目偏移；必须非负。
 * 返回：成功时返回本页条目及匹配总数；空页仍为成功。
 * 失败：参数无效或读取失败时返回错误，不伪造空结果。
 * 副作用：只读查询，不创建或修改任何候选。
 */
```

公开函数在头文件声明处维护完整契约；仅实现文件内的函数在定义处维护，避免复制两份长说明。重载说明差异；访问器说明返回字段的业务含义。QML 函数、信号参数、测试辅助函数以及具有独立业务行为的 lambda 同样适用。

### 5.2 类、对象和每个变量

- 类和结构体说明职责、使用场景、拥有资源、生命周期和线程归属；数据对象说明来源、范围和不变量。
- 每个成员变量逐项说明用途、单位、初始/空值含义、谁修改及谁读取。不能只解释整个类而跳过成员。
- 指针说明拥有或观察关系；容器说明元素及上限；计数说明累计范围；时间说明时区或时间基准；偏移区分字节和 Unicode 码点；版本/修订说明变化规则。
- 枚举逐值解释；QML 自定义属性、信号和关键对象解释职责及数据来源；复杂局部变量同样注释。
- 不给循环自增等显然语句机械写注释，不用重复变量名充数。

### 5.3 函数内部关键段

在输入校验、事务提交、命令重放、修订冲突、线程切换、迟到回调、取消检查点、原文位置换算和凭据读取处解释处理原因及不变量。注释必须与实现一致，禁止写入密钥、私有原文和模型详细响应。

### 5.4 历史代码整改

规范生效不代表全库注释已达标。历史简略/缺失注释登记为欠账；每个修改模块同时整改相关类、成员及函数，XF-26 负责最终逐模块覆盖核查。仅批量删除标签不算详细注释验收，不能以几份合规头文件宣称全库完成。

## 6. 小说处理与事实边界

- 原文不可变；按章节、片段、正文窗口处理，列表分页。禁止把整书塞入单次模型请求或长期驻留的 QML 字符串。
- 字节偏移、Unicode 码点及词元数量明确区分；章节/切片具有稳定标识、原文范围及摘要。
- 主干压缩保留原文映射；否定、时间、数量、规则和对话身份不可无依据删除。压缩比不能代替事实保真度。
- 模型只产生待审候选，原文事实、作者设定、人物说法和模型推断分开保存；接受不等于一律升级为事实。
- 当前提取协议为 `candidate-v3/extract-v3`，四类结构和数量有上限。版本、提示词、输入模式及模型配置影响缓存身份；旧任务不静默升级发送。
- 合法子集及淘汰统计按契约原子提交；引文必须能唯一回到原文，无效项隔离或明确失败。
- 同名、别名仅提供匹配线索；已有实体关联需明确选择并校验同世界、同类型、两侧修订和来源性质。
- 未知时间、强度、坐标保持未知，章节顺序不冒充故事日期和因果。
- 单章抽样、合成千万字测量与真实全书质量分开报告；精确率、召回率、压缩损失及资源峰值必须有实际测量。

## 7. 网络、存储与生命周期

- 默认离线；创建、打开、刷新、切换世界不得发送小说。用户显式启动真实发送；已授权开发验证按现有授权执行并记录范围及用量。
- 暂停/取消停止后续片段，在途调用可能计费；未知结果不自动重发，失败不悄悄扩大预算。
- 密钥只进入系统凭据设施或测试内存替身，不写源码、日志、报告、导出和 Git 历史。
- SQL 参数绑定；事务不跨网络等待。候选、证据、接受映射、世界投影、命令日志按需同事务提交。
- 写入校验预期修订和幂等命令；迁移可回滚，不猜测补写历史事实。
- GUI 线程更新界面；工作线程使用自己的数据库连接和值对象。异步结果携带世界/工作区身份和代次，过期回调丢弃。
- QObject、智能指针、线程池和任务所有权明确；退出和销毁安全处理在途任务。

## 8. 验证与阶段上传

核心改动运行核心 CTest；界面/视图模型改动运行一键构建、完整 CTest，并检查深浅主题实际页面；协议改动补契约回归。失败后定位并重跑受影响检查，不能用旧结果声称新修改通过。

提交前检查：功能正常及失败路径、空首启、测试与生产隔离、中文选项和默认弹窗、相关函数与成员注释、凭据和私有素材排除、文档状态准确。检查范围和未测项必须真实记录。

每完成有意义阶段，用中文提交说明上传 GitHub，核对远端提交和持续集成结果，再正常快进或合并主分支。时间使用真实时间，不伪造过去一个月的提交日期。构建成功不等于功能验收，源码扫描不等于运行时无污染，局部通过不等于整个软件完成。
